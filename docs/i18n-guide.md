# I18n Maintenance & Development Guide

The game ships in a single language: **`en-US`**. It is the default, fallback, schema, and source-of-truth locale declared in `static/locales/registry.json`. The i18n machinery (gettext on the backend, Vue I18n on the frontend) is kept so that all user-visible text lives in locale resources rather than in code, and so that another language can be added later without refactoring (see `docs/i18n-add-locale.md`).

Related docs and rules:

- Frontend specifics: `docs/frontend-i18n.md`
- Adding a language: `docs/i18n-add-locale.md`
- Agent rule: `.cursor/rules/i18n.mdc`
- Terminology: `docs/glossary.csv` (columns `english,category,subcategory,notes`)

## 1. Where Text Lives

```text
static/locales/
├── registry.json                  # Locale registry (single source of truth)
└── en-US/
    ├── modules/                   # SOURCE: dynamic text used by t() in Python code
    │   ├── action.po
    │   ├── battle.po
    │   ├── ui.po
    │   └── ...
    ├── game_configs_modules/      # SOURCE: translations for CSV name_id/desc_id keys
    │   ├── sect.po
    │   ├── weapon.po
    │   └── ...
    ├── LC_MESSAGES/               # BUILD OUTPUT: never edit by hand
    │   ├── messages.po / .mo      # merged from modules/
    │   └── game_configs.po / .mo  # merged from game_configs_modules/
    ├── templates/*.txt            # LLM prompt templates
    └── game_configs/*.csv         # locale-specific CSV data (e.g. given_name.csv, last_name.csv)

src/i18n/
├── __init__.py                    # exports t()
├── locale_registry.py             # Python helpers for reading registry.json
└── template_resolver.py           # resolves templates/*.txt for the current locale

web/src/locales/
├── registry.ts                    # frontend view of registry.json
├── index.ts                       # auto-loads JSON modules via import.meta.glob
└── en-US/*.json                   # frontend UI strings
```

### 1.1 Locale Registry

`static/locales/registry.json` is the single source of truth for which locales exist. Python helpers (`src/i18n/locale_registry.py`), i18n tools, locale tests, and the frontend (`web/src/locales/registry.ts`) all read it.

- `default_locale`: default language
- `fallback_locale`: fallback when a translation is missing
- `schema_locale`: reference locale for frontend message typing
- `locales`: registered locales (`code`, `label`, `html_lang`, `enabled`, `source_of_truth`)

Never hardcode locale lists in scripts, tests, or runtime code; read them from the registry.

## 2. Core Rules

1. **Edit sources, not build products.** Edit `modules/*.po` and `game_configs_modules/*.po`. `LC_MESSAGES/messages.po` and `LC_MESSAGES/game_configs.po` (and their `.mo` files) are generated by `python tools/i18n/build_mo.py`.
2. **Rebuild after every `.po` change**: `python tools/i18n/build_mo.py`. Without it, runtime will not see the change. Commit the generated `.mo` files.
3. **`msgid` is English source text or a stable key.** For example `t("{name} attacked", name=name)` or `ACTION_NAME_ID = "my_action_name"`.
4. **No hardcoded user-visible text in Python logic.** Route it through `t()`, a CSV `*_id` key, or a locale template.
5. **Short slots stay short.** Keys used in narrow UI slots (`title`, `label`, `tab`, `button`, `badge`, `status`, `*_short`, menu items, status-bar entries, card titles) must be concise. Put full explanations in separate `*_desc` / help / tooltip keys instead of letting one long string serve both a button and a dialog.
6. **LLM-generated text is not translated.** Constraints or prompt fragments that shape generated text (`backstory`, `thinking`, goals, ...) belong in `templates/*.txt` or translation keys, not in Python string literals.
7. **No plurals.** Write strings that avoid plural forms, e.g. `"Found {amount} spirit stone(s)"`.
8. **Formatting**: UTF-8 without BOM, no duplicate headers in module files, one empty line between entries.

## 3. Workflow: Dynamic Text (Python Code)

1. Add the entry to the appropriate `static/locales/en-US/modules/<category>.po`.
2. Use it in code:
   ```python
   from src.i18n import t
   # Before: f"{name} attacked"
   # After:  t("{name} attacked", name=name)
   ```
3. Run `python tools/i18n/build_mo.py`.

## 4. Workflow: Game Configs (CSV)

Use this when adding rows to CSV files under `static/game_configs/`.

1. Add the row with `name_id` / `desc_id` (and any other `*_id` columns), e.g. `ITEM_SWORD_NAME`. The `name` / `desc` columns are kept only as reference text.
2. Optionally refresh the POT template (`src/i18n/locales/templates/game_configs.pot`):
   ```bash
   python tools/i18n/extract_csv.py
   ```
3. Add the translations to `static/locales/en-US/game_configs_modules/<category>.po`.
4. Run `python tools/i18n/build_mo.py`. At runtime the CSV loader looks up each `*_id` via `t()` in the `game_configs` domain.

Name pools (`given_name.csv`, `last_name.csv`) and other locale-specific CSV data live directly in `static/locales/en-US/game_configs/` and do **not** go through PO/MO.

## 5. Workflow: LLM Prompt Templates

Prompt templates live in `static/locales/en-US/templates/*.txt` and are resolved by `src/i18n/template_resolver.py` (current locale, then fallback/source locale). Add or edit templates there instead of embedding prompt text in Python.

## 6. Validation

```bash
python tools/i18n/build_mo.py
pytest tests/test_backend_locales.py tests/test_frontend_locales.py tests/test_i18n_modules.py tests/test_i18n_integrity.py
cd web && npm run type-check
```

- `tests/test_backend_locales.py`: duplicate `msgid`s in merged `messages.po`, module consistency across registered locales, template file sets.
- `tests/test_i18n_modules.py`: module directory structure and merged `messages.po` integrity.
- `tests/test_i18n_integrity.py`: every CSV `*_id` has a translation, `msgid` conventions, every `msgid` used in code is defined, format parameters match.
- `tests/test_frontend_locales.py`: frontend JSON module/key consistency.

Other helpers in `tools/i18n/` (e.g. `generate_missing_report.py`, `compare_msgids_across_locales.py`, `cleanup_po_comments.py`, `split_action_module.py`) are mainly useful once more than one locale is registered or when reorganizing modules.

## 7. Windows PowerShell Warning

**Do NOT use redirection (`>>`) in Windows PowerShell to append to `.po` files.** It writes UTF-16LE into UTF-8 files, producing `\x00` null bytes and corrupting them. If that happens, stop writing, read the file as binary, strip `b'\x00'`, and save it back as UTF-8 without BOM.

## 8. Implementation Patterns by Domain

### 8.1 Actions & MutualActions

**Pattern:** class variables for IDs, `t()` for dynamic text.

```python
class MyAction(Action):
    # IDs
    ACTION_NAME_ID = "my_action_name"
    DESC_ID = "my_action_desc"
    REQUIREMENTS_ID = "my_action_req"

    # Optional: for MutualActions or Actions with prompts
    STORY_PROMPT_ID = "my_action_story_prompt"

    # Dynamic text during execution
    def start(self, ...):
        from src.i18n import t
        msg = t("{actor} performs action on {target}", actor=self.avatar.name, target=target.name)
```

**Location:** `static/locales/en-US/modules/action.po` and, for larger groups, sibling files such as `action_combat.po`, `action_progression.po`, and `action_world.po`.

### 8.2 Effects

**Pattern:** ID mapping and JSON overrides.

1. **Standard effects** are mapped in `src/classes/effect/desc.py` (key `extra_max_hp` -> msgid `effect_extra_max_hp`).
2. **Custom descriptions (JSON/CSV)**:
   - `_desc` overrides the whole description with a translation key.
   - `when_desc` replaces the condition expression with a human-readable translation key.

   ```json
   {
       "extra_attack": 5,
       "when": "avatar.hp < 50",
       "when_desc": "condition_low_hp",  // msgstr: "When HP is low"
       "_desc": "effect_berzerk_mode"    // msgstr: "Berzerk Mode: Attack +5 when HP is low"
   }
   ```

**Location:** `static/locales/en-US/modules/effect.po`.

### 8.3 Avatar Info

**Pattern:** translated dict keys.

```python
def get_avatar_info(self):
    from src.i18n import t
    return {
        t("Name"): self.name,
        t("Level"): self.level,
        t("Sect"): self.sect.name if self.sect else t("Rogue Cultivator"),
    }
```

**Location:** `static/locales/en-US/modules/avatar.po` or `ui.po`.

### 8.4 Gatherings (Events)

**Pattern:** class method for storyteller prompts.

```python
@register_gathering
class Auction(Gathering):
    STORY_PROMPT_ID = "auction_story_prompt"

    @classmethod
    def get_story_prompt(cls) -> str:
        from src.i18n import t
        return t(cls.STORY_PROMPT_ID)

    def get_info(self, world) -> str:
        return t("Auction in progress...")
```

**Location:** `static/locales/en-US/modules/gathering.po`.
